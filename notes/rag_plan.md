# CareerFit RAG 기획안 (작업 지시용)

새 세션에서 이 파일을 그대로 붙여 넣거나 "notes/rag_plan.md 대로 이어서 해라"로 쓴다.
고정값의 원본은 `notes/rag_experiment_2026-11-05.md`(본문 + 부록 A)이고, 이 문서는 순서와 규칙만 담는다. 둘이 다르면 사전 등록 노트가 맞다.

## 시작할 때
CareerFit 에 RAG 검색 기능을 이어서 구현한다. 처음부터 다시 만들지 않고 커밋된 단계 위에서 계속한다.
먼저 `CLAUDE.md`, `notes/rag_experiment_2026-11-05.md`, `src/rag/`, `git log --oneline -15` 를 읽고
아래 "진행 상태"와 실제 코드가 맞는지 확인한 뒤, 현재 상태 3~5줄과 이번에 할 단계를 보여 주고 내 확인을 받아라.

## 배경
- 나는 LLM 애플리케이션·데이터 엔지니어 직무 지원자다. 지원 공고 필수가 "LLM·RAG 기본 지식", 우대가 "벡터 검색·RAG 솔루션 경험"인데
  포트폴리오(https://kevin2483.github.io/)에 RAG 가 없다.
- 레디포스트는 데이터가 표라 RAG 대신 SQL 도구를 택했다. CareerFit 은 채용공고(비정형)라 RAG 가 맞다.
  두 프로젝트로 "RAG 가 필요한 곳과 아닌 곳을 구분한다"는 이야기를 만든다. 포트폴리오 정체성은 "만드는 것보다 재는 장치를 먼저 세운다".
- 목적은 기능 추가다. 개념 설명은 쓰지 말고 설계 판단과 실제 수치만 보고하라.

## 단계 (이 순서대로)
1. **필터** — `chunk.py` 에 `annual_from`·직무 메타데이터 추가. 질문의 `filter` 를 모든 방식에 똑같이 거는 함수 하나. 규칙은 부록 A2.
2. **hybrid** — bm25·vector 각 상위 50(필터 통과분)을 RRF k=60 으로 결합. 점수가 아니라 순위로 합친다.
3. **실행 기록** — 방식별 `data/processed/rag_runs/<방식>.jsonl` (qid, rank, chunk_id, score). 원문 없이 지표를 재현하기 위함.
4. **변형** — `ctx_prefix`, `sec3` 실행 기록. 검색 지연 중앙값·p90 (기준은 부록 A3).
5. **리랭커** — 후보와 장단점(메모리 포함)을 제시 → 내가 고르면 노트 표에 추가 커밋 → 실행 기록.
6. **판정 도구와 판정** — 6개 방식 상위 10 합집합을 방식 이름을 가리고 섞어, 기본값 없이 한 건씩 y/n 을 강제하는 CLI
   (`src/label/pool_cli.py` 구조 참고, 엔터 넘기기·일괄 처리 금지). 결과 `data/labeled/rag_judgments.jsonl`. 10% 재판정으로 자기 일치율.
   판정은 내가 한다. 도구는 1~3 단계와 함께 미리 만들어도 되지만 실행은 5단계가 끝난 뒤 한 번.
7. **평가** — Recall@5(주), MRR@5, nDCG@5, 공고 단위 Recall@5 (부록 A7 에서 @10 → @5). D 유형은 상위 1 점수 분포만. 주 비교 5쌍의 짝지은 부트스트랩 CI
   (`src/eval/bootstrap_ci.py` 방식). `data/processed/rag_comparison.csv` (항목·값·근거). `make reproduce`·CI 에 추가(커밋된 runs·judgments 만 읽게).
   미판정 청크가 있으면 중단.
8. **생성** — 별도 사전 등록 문서를 먼저 쓴다. 검색된 청크만으로 답하고, 답을 주장 단위로 나눠 근거 청크에 있는지 검사.
   LLM 판정을 쓰려면 사람 판정 20개 이상과 일치율을 먼저 잰다. 범위를 줄이더라도 이 단계는 반드시 끝낸다
   (질문 → 근거 인용이 붙은 답까지 한 번은 끝까지 가야 "RAG 를 만들었다"가 된다).
9. **정리** — README, 포트폴리오용 비교표·한계. 청크 원문이 비공개라 공개 데모에 검색 탭을 넣을 수 없으니 로컬 전용 시연(영상·스크린샷)으로 할지 여기서 정한다.

질문이 채워지기 전에 할 수 있는 것: 1·2·3·6·7 의 코드와 테스트(합성 데이터로). 실제 질문으로 검색을 돌리는 것은 질문 30개가 커밋된 뒤.

## 반드시 지킬 것
- 질문 30개와 정답 판정은 내가 한다. 질문을 쓰거나 정답을 채우지 마라 (CLAUDE.md ④, 순환논리).
- 사전 등록 노트의 방식·파라미터를 결과를 보고 바꾸지 마라. 다시 하려면 새 사전 등록 문서를 쓰고 "2차"로 적는다.
- 이 맥은 메모리 8.6GB 다. bge-m3 는 시스템을 두 번 멈추게 해서 이번 실험에서 뺐다. 큰 모델은 내가 허락한 시간에만, 실행 전에 메모리를 먼저 재라.
- 새 패키지 추가·기존 코드 큰 변경 전에는 묻는다. 날짜 하드코딩 금지(`--date`, `resolve_date`), JSONL 은 `read_jsonl` 만.
- 숫자는 실제로 돌린 결과만. 추정은 추정이라고 밝힌다. 방식 간 차이는 CI 가 0 을 포함하면 "확정 불가".
- 커밋은 단계별로, 푸시는 내 확인 후.
