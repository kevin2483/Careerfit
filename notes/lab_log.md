## 2026-07-25 | [결정] 스킬 과제 범위 축소 (regex 추출 + 빈도표)

- 원래 처리 5단계 중 3단계(LLM 추출)·4단계(regex vs LLM precision/recall/F1)를 오늘 범위에서 뺌.
- 근거 1: LLM은 비결정적이라 "같은 입력=같은 출력" 재현 검증이 불가능 → 오늘 스킬 성격(재현 가능한 리포트)에 안 맞음.

- 오늘 범위 확정: 1단계 로드·검증 → 2단계 regex 베이스라인 추출 → 3단계 직무별 빈도표 집계.

## 2026-08-13 — regex 경계 패치 + 정답셋 결함 규명

### 결론 먼저

F1 0.915 → 0.892. **하락이 성과다.** 0.915는 regex 출력으로 만든 정답셋을

### 1. 한글 조사 미매칭 (해결)

`\b`는 `\w` 기준이고 파이썬 `\w`는 한글을 포함한다. 조사가 붙으면 경계가 사라진다.
→ `src/extract/boundary.py` 신규. ASCII 경계 + 짧은 alias(≤2자)는 조사 화이트리스트.
`compile_patterns()`에서 `re.escape` 줄 제거 후 `build_alias_pattern()`으로 교체.

**전체 1,132건 결과: 태그 7,360 → 7,889 (+529, +7.2%). 문서 490/892건(54.9%)에서 태그셋 변화.**
증가 상위: C++ +80, Python +56, SQL +56, 대용량데이터처리 +46, 데이터품질관리 +26,
대시보드 +25, AI Agent +24, 파이프라인설계운영 +23.
→ **한글 canonical = field 2에 집중 타격이었다.** 계획서가 "개선효과는 ②에서 측정"이라
한 바로 그 필드가 조사 버그로 깎여 있었다.

감소는 전부 의도한 오탐 제거: R −70(R&D), C −50(C++ 안의 C),
JavaScript −23(Node.js 안의 js), C++ −3(llama.cpp).

#### 버린 시도 — 경계 문자 집합 v1, v2

- **v1 실패**: 경계 클래스에 `-`, `.` 포함 → `TensorRT-LLM`, `docker-swarm`,
  `LLM-as-a-judge`, `End-to-End.` 전부 깨짐. 하이픈 복합어가 공고에 매우 흔하다.
- **v2 실패**: `-` 제외로 위는 해결했으나 두 건 남음.
  `C++17/20` 미매칭(`+`로 끝나는 alias 뒤 숫자), `2.Python`(번호 목록의 점).
- **v3 채택**: `.`을 경계 문자에서 빼고 `(?<![A-Za-z]\.)`로 대체 →
  식별자 내부 점(Node.js, llama.cpp)만 막고 번호 목록은 통과.
  alias가 영숫자로 끝나지 않으면(C++, C#) 후행 숫자 허용.
  셀프테스트 37건(실제 공고 원문 케이스 포함) 전부 통과.

**교훈: 경계 규칙은 실제 공고 원문으로 검증해야 한다. 합성 테스트만으로는 안 잡힌다.**
