# 프롬프트 변형 실험 — 사전 등록 (2026-10-29, 실행 전 작성)

## 왜 사전 등록인가
정답셋은 38건뿐이고 그것이 유일한 평가 데이터다. 그 38건을 보며 프롬프트를 반복 수정하면 시험지를 보고 공부하는
셈이라 점수가 올라도 일반화를 주장할 수 없다. 그래서 **변형을 실행 전에 고정하고, 각 변형을 정확히 한 번 돌리고,
결과가 어떻든 그대로 적는다.** 이 문서는 결과 파일보다 먼저 커밋된다 (git log 로 순서 확인 가능).

## 대상
- 모델: `claude-haiku-4-5-20251001` (네 방식 중 가장 싸고 F1 이 가장 낮아 개선 여지가 큼. 기준 F1 0.828 [0.785, 0.865])
- 데이터: 정답셋 38건 (`data/labeled/gold_ids.txt`), 사전 v2, 같은 채점기·같은 부트스트랩(seed 42, B=10,000)
- 비용 상한: 변형당 약 $0.12, 합계 $0.4 이내

## 변형 (각 1회 실행, 수정 금지)
| 이름 | 바꾸는 것 | 가설 | 주로 움직일 지표 |
|---|---|---|---|
| `alias` | 허용 태그 목록에서 서술형(field 2) 태그 33개에 사전의 alias 를 "표현 예"로 덧붙인다(사전 순서대로 최대 6개). 사전에서 기계적으로 생성, 손으로 쓴 설명 없음 | 서술형 태그의 표현 폭을 알려 주면 ② 누락이 준다 | ② recall ↑ |
| `criteria` | 사람이 쓴 라벨링 기준(`notes/labeling_criteria.md` 판단 3·4: 명시 ① / 의미 명확한 서술형 ② 인정, 근거 약한 추측 ③ 제외, 상위개념 대신 하위 태그)을 시스템 프롬프트에 그대로 넣는다 | 정답셋을 만든 사람과 같은 기준을 주면 ③ 유형 오탐이 준다 | precision ↑ |
| `schema` | 구조화 출력(`output_config.format`, JSON 스키마의 enum = canonical 106개)으로 출력 형식과 라벨 공간을 API 가 강제한다 | 환각 태그·파싱 실패가 0 이 된다. F1 은 거의 안 변할 것 | 환각 0, 파싱실패 0 |

변형은 서로 독립이다(겹쳐 쓰지 않는다). 세 변형 모두 기준 프롬프트에 한 가지씩만 더한다.

## 판정 기준 (실행 전 고정)
- 기준(haiku base)과의 **짝지은 F1 차이의 95% CI 가 0 을 넘으면 "개선 확정"**, 포함하면 "확정 불가". 점추정만으로 주장하지 않는다.
- 환각 태그 수·파싱 실패 수는 `_summary.json` 에서 그대로 읽는다.
- 결과가 나쁘거나 차이가 없어도 README 에 그대로 적는다. 변형을 고쳐서 다시 돌리지 않는다.
  (다시 돌리고 싶으면 새 사전 등록 문서를 쓰고, 그 결과는 "2차"로 따로 적는다.)
