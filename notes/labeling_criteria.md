# 라벨링 판단 기준 (면접 방어용)

**전제 — 왜 정답셋을 직접 만들었나**
원티드 skill_tags는 범용 웹 스택(Spring·React)이 데이터 직무에 섞여 신뢰 불가.
자체 정답셋을 구축해 정량 평가의 기준으로 삼았다.

## 판단 1 — 우대사항 역량도 정답에 넣는가
- 결정: 넣는다. 단, 어느 섹션(필수/우대)에서 나왔는지 기록.
- 근거: 우대를 빼면 정보 손실. 섹션 기록 시 "필수 vs 우대 역량 트렌드" 분리 분석 가능.

## 판단 2 — 사전에 없는 역량이 나오면
- 결정: 정답에 넣고, 사전 v1 후보로 별도 기록.
- 근거: 사전 기준으로만 평가하면 커버리지 한계가 안 드러남. 새 역량 포함해야 진짜 재현율 측정 가능 + 사전 개선(v1)으로 순환.

## 판단 3 — 상위개념(parent)을 정답으로 치는가
- 결정: 하위 태그(AWS)를 정답, 상위개념(클라우드)은 별도 집계.
- 근거: 계획서 4번 원칙. 상위개념으로 뭉개면 구체적 역량 요구가 사라짐.

## 판단 4 — "명시" vs "의미상 추론" 어디까지 (핵심)
- 결정: 3단계 기준.
  ① 명시된 기술/도구(단어 그대로) → 정답
  ② 의미가 명확한 서술형(예: "운영 가능한 ML 시스템 구축"=MLOps) → 정답
  ③ 근거 약한 추측(한 단어만 걸리고 문맥 애매) → 제외
- 근거: 엄격(①만)하면 정답이 regex와 비슷해져 LLM 우위가 안 보임. 계획서 4번이
  "서술형·암묵조건에서 개선효과 측정"이라 했으므로 ②를 인정해야 LLM이 이기는 구간이 드러남.
  ③은 배제해 정답셋이 과도하게 관대해지는 것 방지.
- 적용 사례(1번 공고): "운영 가능한 ML 시스템 구축"→MLOps 인정(②).
  "실험 데이터 기반"만으론 A/B테스트 근거 약함→제외(③).

## 판단 5 — field 3(암묵조건) 태그
- 결정: 정답셋엔 포함하되 성능 평가 집계에서는 제외.
- 근거: 거의 모든 공고에 등장해 변별력 없고 regex로 문맥 매칭 불가.
  쏠림(①명시46/②서술25/③암묵1) 자체가 "암묵조건은 규칙 기반 영역이 아니다"라는 발견.

## 판단 6 — 라벨링 표본 추출
- 결정: 07-30분(892 고유 공고)에서 직무별 15건씩 60건. 중복은 첫 등장 직무로 귀속,
  걸린 직무 이력(all_jobs) 보존.
- 근거: 950건 중 219건(23%)이 복수 직무 중복 등장 = 직무 경계 흐릿. dedup하되 겹침 정보는 6번용 보존.

## 판단 7 — 라벨링 순환논리 회피 (방법론 급소)
- 결정: regex 결과를 미리 채운 검수 방식. 단 기준은 사람이 세우고 본문 전문을 함께 실어
  regex 누락을 직접 잡게 함. AI 초벌 판단을 넣어도 최종 확정은 사람 검수를 거침.
- 근거: LLM이 만든 정답으로 LLM을 평가하면 순환논리. 정답의 기준과 최종 확정은 사람이 쥐어야 평가가 유효.
