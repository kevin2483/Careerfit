# 검색(RAG) 방식 비교 실험 — 사전 등록 (2026-11-05, 실행 전 작성)

## 왜 사전 등록인가
검색 정답셋은 질문 30개 안팎뿐이다. 그 30개를 보며 BM25 파라미터·청크 크기·RRF 상수를 고치면 시험지를 보고 공부하는 셈이다.
그래서 **방식·변형·파라미터·판정 기준을 실행 전에 이 문서로 고정하고, 각 방식을 한 번 돌리고, 결과가 어떻든 그대로 적는다.**
이 문서는 정답 판정·결과 파일보다 먼저 커밋된다.

## 기능과 코퍼스
- 기능: 자연어 질문 → 그 조건을 담은 **공고 문단(청크)** 상위 k 를 근거로 돌려준다. 이후 단계에서 근거를 붙인 답변 생성.
- 코퍼스: `--date 2026-07-30`, 고유 공고 892건 → 청크 4,573개 (`src/rag/chunk.py`, 구역 5개, 1,500자 초과 구역만 분할).
- 경력·직무 같은 **구조화 조건은 검색이 아니라 필터**로 처리한다. 사전 확인(질의 3개)에서 BM25·벡터 모두 "신입 가능"을
  본문으로 거르지 못했다("Senior", "5년 이상" 공고가 1위). 질문의 필터 조건은 질문 파일에 따로 적고, 모든 방식에 똑같이 적용한다.

## 질문 세트 (사용자가 작성, AI 가 쓰지 않는다)
- 파일: `data/labeled/rag_queries.jsonl` (질문은 원문이 아니므로 레포에 포함)
- 한 줄 형식: `{"qid": "q01", "type": "A", "question": "...", "filter": {"annual_max": 0, "jobs": ["de"]} }` (filter 는 없으면 `{}`)
- 유형과 개수 (합계 30):

| 유형 | 개수 | 무엇을 묻나 | 예시 (형식 참고용, 그대로 쓰지 않는다) |
|---|---|---|---|
| A 명시 기술 | 8 | 기술명이 질문에 그대로 있음 | Airflow 로 배치 파이프라인을 운영하는 곳 |
| B 바꿔 쓴 역량 | 10 | 공고와 다른 말로 표현한 역량·업무 | 모델을 실제 서비스에 올려 본 사람을 찾는 곳 |
| C 근무조건 | 6 | 복지·근무 형태·환경 | 집에서 일할 수 있는 데이터 직무 |
| D 자료 밖 | 6 | 코퍼스에 답이 없을 질문 (정답 0개가 정답) | 연봉 1억 이상 보장하는 공고 |

- 작성 규칙
  1. **검색 결과를 보기 전에** 30개를 다 쓰고 커밋한다. 결과를 보고 질문을 고치지 않는다.
  2. 공고 문장을 복사하지 않는다. 특정 공고를 떠올리며 쓰지 않는다 (BM25 에 유리해지는 누수 방지).
  3. A 유형만 기술명을 그대로 쓴다. B 는 기술명·사전 alias 를 피한다.

## 정답 판정 (블라인드 풀링, 사람 판정)
- 후보 풀: 질문마다 아래 모든 방식·변형의 상위 10 청크 합집합. 방식 이름을 가리고 섞는다.
- 판정 단위: 청크. "이 문단이 질문 조건을 직접 담고 있나" y/n. 공고 단위 정답은 청크 정답에서 유도한다.
- 판정 UI 는 **기본값 없이 하나씩 y/n** 을 강제한다. (2026-10-30 `--batch` 판정이 엔터 넘기기로 정답셋을 오염시킨 교훈. lab_log)
- 풀에 없는 정답은 모른다. 따라서 Recall 은 "풀 안에서 찾은 정답 대비"이며, 이 한계를 결과에 같이 적는다.

## 비교 방식 (각 1회, 파라미터 고정)
| 이름 | 내용 | 고정값 |
|---|---|---|
| `bm25` | 한글 2-gram + 영문 단어 토큰, Okapi BM25 | k1=1.5, b=0.75 |
| `vector` | multilingual-e5-small, 코사인 | query:/passage: 접두어, 512 토큰 |
| `hybrid` | bm25 + vector 순위를 RRF 로 결합 | RRF k=60, 각 방식 상위 50 |
| `hybrid_rerank` | hybrid 상위 20 을 리랭커로 재정렬 | 리랭커는 아래 별도 결정 후 이 표에 추가 커밋 |

변형 (vector 기준 하나씩만 바꾼다):
| 이름 | 바꾸는 것 | 가설 |
|---|---|---|
| `ctx_prefix` | 청크 앞에 "제목 · 회사 · 구역명" 을 붙여 임베딩 (문맥적 임베딩) | 짧은 우대사항 문단이 어느 직무인지 알게 되어 B 유형 recall ↑ |
| `sec3` | intro·benefits 를 빼고 3구역만 색인 | 회사 홍보문 잡음이 줄어 A·B 정밀도 ↑, 대신 C 유형 recall ↓ |
| `bge_m3` | 임베딩을 bge-m3 로 (맥을 쓰지 않는 시간에 1회) | 5배 큰 모델이 recall 을 올리는지. 차이가 없으면 작은 모델로 충분 |

## 지표와 판정 기준 (실행 전 고정)
- 주 지표: 청크 단위 **Recall@10**. 보조: **MRR@10**, 공고 단위 Recall@10.
- D 유형(정답 0개)은 Recall 에서 빼고, 별도로 "상위 1 유사도/점수" 분포만 보고한다 (임계값 거절은 이번 범위 밖).
- 방식 간 차이는 질문 단위 부트스트랩(B=10,000, seed 42) **짝지은 차이 95% CI 가 0 을 넘으면 "확정"**, 포함하면 "확정 불가".
  질문 24개(D 제외)로는 대부분 확정 불가가 나올 수 있다. 그래도 그대로 적는다.
- 비기능: 질의 1건당 검색 지연(임베딩 포함) 중앙값·p90 을 로컬에서 재서 함께 적는다. 목표는 p90 1초 이내.
- 결과가 나빠도 방식·변형을 고쳐 다시 돌리지 않는다. 다시 하려면 새 사전 등록 문서를 쓰고 "2차" 로 적는다.

## 생성 단계 (검색 비교 뒤, 별도 사전 등록)
- 검색된 청크만 보고 답하게 하고, 답을 주장(claim) 단위로 나눠 각 주장이 인용 청크에 실제로 있는지 검사한다(충실성 = 뒷받침 주장 / 전체 주장).
- LLM 판정을 쓰려면 먼저 사람이 20개 이상을 직접 판정해 LLM 판정과의 일치율을 잰다. 일치율 없이 LLM 점수를 결론에 쓰지 않는다.

## 부록 A (2026-11-10, 실행 전 추가)
위 본문은 고치지 않는다. 이 부록은 **질문 30개가 아직 비어 있고 어떤 방식도 실제 질문으로 돌리지 않은 시점**에,
본문이 정하지 않아 실행 중에 임의로 정하게 될 빈칸을 미리 메운 것이다. 본문과 충돌하는 항목은 A4(bge_m3 제외) 하나뿐이다.

### A1. 실행 순서 — 판정은 모든 방식이 끝난 뒤 한 번
- 본문의 후보 풀은 "모든 방식·변형 상위 10 합집합"이다. 일부 방식만으로 먼저 판정하면 나중 방식이 가져온 청크는
  "새 방식에서 나왔다"는 것을 판정자가 알게 되어 블라인드가 깨진다.
- 순서: 필터 → hybrid → 실행 기록 → 변형(ctx_prefix, sec3) → 리랭커 결정·실행 → **판정 1회** → 평가.
- 평가 스크립트는 어떤 방식의 상위 10 에 미판정 청크가 하나라도 있으면 수치를 내지 않고 중단한다. 미판정을 오답으로 치지 않는다.
- 판정 화면은 방식·변형과 무관하게 같은 것을 보여 준다: 질문, 필터, 공고 제목·회사·구역명, 청크 원문. (ctx_prefix 의 접두어는 임베딩에만 쓴다.)
- 자기 일치율: 1차 판정이 끝난 뒤 판정 쌍의 10%(seed 42 무작위)를 이전 답을 가린 채 다시 판정해 일치율을 적는다. 점수에는 1차 판정만 쓴다.

### A2. 필터 규칙
| 항목 | 값 | 근거 |
|---|---|---|
| 적용 시점 | 상위 k 를 자르기 **전** (사전 필터). hybrid 의 "각 방식 상위 50" 도 필터 통과 청크 중 상위 50 | 사후 필터는 필터 질문에서 결과가 10개 미만이 됨 |
| BM25 통계(IDF·평균 길이) | 그 색인 전체 기준으로 고정. 필터는 후보 마스크로만 씀 (sec3 은 sec3 색인 전체) | 질문마다 통계가 달라지면 필터 유무가 점수 체계를 바꿈 |
| `annual_max: 0` | `annual_from == 0` 인 공고만 통과. `None`(미기재)은 제외 | CLAUDE.md ② 정의상 None 은 "신입 가능"이 확인되지 않은 것. 제외된 공고 수를 결과에 같이 적는다 |
| `jobs` | 공고의 직무 중 하나라도 목록에 있으면 통과 (job_id 병합으로 직무가 여럿일 수 있음) | chunk.py 의 중복 병합 |

### A3. 지표 보충
- 보조 지표에 **nDCG@10** 추가 (이진 이득, 이상 순위는 풀 안 정답 수와 10 중 작은 값까지 1).
  이유: 정답 청크가 10개를 넘는 질문은 Recall@10 상한이 1 미만이라 방식 간 차이가 눌린다. 주 지표는 여전히 Recall@10 이다.
- A~C 질문인데 풀 안 정답이 0개면 Recall·MRR·nDCG 평균에서 빼고, 그런 질문 수와 qid 를 결과에 적는다.
- D 질문에서 정답(y)이 나오면 유형을 바꾸지 않는다. Recall 에 넣지 않고 "D 유형 중 정답이 발견된 질문 수"로 따로 적는다.
- D 유형의 상위 1 점수 분포는 `bm25`, `vector`, `ctx_prefix`, `sec3` 만 보고한다. RRF 점수는 순위에서만 나와 질문과 무관하게 거의 같다.
- **주 비교 5쌍** (이 다섯만 "확정/확정 불가"를 판정한다. 나머지 쌍은 참고 표로만 싣고 결론에 쓰지 않는다):
  `hybrid − bm25`, `hybrid − vector`, `ctx_prefix − vector`, `sec3 − vector`, `hybrid_rerank − hybrid`
- 지연 측정: 모델 로딩 제외, 예열 질의 1건 뒤 질문 30개를 각 1회. 질의 임베딩 시간 포함. 리랭커 포함 방식도 같은 기준으로 재고 목표(p90 1초)를 넘으면 넘은 대로 적는다.

### A4. bge_m3 변형 제외 (본문 변경)
- 본문 변형 표의 `bge_m3` 는 이번 실험에서 **실행하지 않는다.** 이 맥(메모리 8.6GB)에서 bge-m3 가 시스템을 두 번 멈추게 했고,
  풀 구성에 들어 있으면 이 한 방식 때문에 판정 전체가 묶인다.
- 따라서 풀·비교 대상은 6개다: `bm25`, `vector`, `hybrid`, `hybrid_rerank`, `ctx_prefix`, `sec3`.
- "더 큰 임베딩 모델이 recall 을 올리는가"는 이번 결과로 답하지 않으며 한계에 그대로 적는다. 하려면 새 사전 등록 문서(2차)로 한다.
- 리랭커를 고를 때도 같은 메모리 제약을 적용한다. 실행 전에 메모리를 먼저 잰다.
