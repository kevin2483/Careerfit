# 에이전트 최종 검토 · 참고 자료

> `SKILL.md` 가 필요할 때만 이 파일을 읽는다. 처음부터 다 읽히지 않는다.
> 쓰는 자리: 경로를 못 찾을 때 · 축이 미통과일 때 · 한 축에서 5분 넘게 막혔을 때.
>
> **합격선은 `SKILL.md` 가 정한다.** 품질 4개 중 3개 · 재현성 4개 중 3개 · 안전 3개 전부.
> 이 파일은 합격선을 바꾸지 않는다.
>
> **산출은 둘이다.** `검토결과.md` 와 `검토결과.html`

---

## 1. 경로를 못 찾을 때

| 증상 | 이렇게 합니다 |
|---|---|
| 경로를 붙여 넣었는데 못 읽음 | 공백이나 한글이 있으면 따옴표로 감싼다. `"/Users/이름/Desktop/공고 팀"` |
| 끌어다 놓았는데 이상한 글자가 붙음 | 앞뒤 따옴표나 `file://` 를 떼어낸다 |
| 폴더는 맞는데 `CLAUDE.md` 가 없음 | 한 단계 아래 폴더를 본다. 작업 폴더 안에 또 폴더를 만든 경우가 흔하다 |
| 폴더가 여러 개라 어느 것인지 모름 | 바탕화면과 문서 폴더에서 `CLAUDE.md` 를 찾아 목록으로 보여주고 고르게 한다 |
| `.claude` 폴더가 안 보임 | 숨김 파일이 꺼진 것이다. 맥은 `Command + Shift + .`, 윈도우는 보기 메뉴 |

**세 번 물었는데도 못 찾으면** 그 자리에서 최소 폴더를 만든다.
`CLAUDE.md` 여섯 칸 + 담당자 한 명 + 견본 자료 열 건. 최소로만 만들고 바로 3축으로 간다.
빈손으로 나가는 것보다 낫다.

## 2. ① 품질 미통과

| 증상 | 원인 | 이렇게 합니다 |
|---|---|---|
| 칸 이름이 `CLAUDE.md` ③과 다름 | ③에 칸 이름을 안 적었거나 뒤에 바꿈 | ③에 열 이름을 다 적고 다시 돌린다 |
| 원본에 없는 값이 섞임 | 담당자에게 "정리해줘"만 시킴 | 담당자 정의의 "하는 일"에 `원문에 없는 내용은 넣지 않는다` 한 줄 |
| 항목이 빠짐 | 자료가 지저분해서 못 읽은 것 | 읽힌 것만 남기고 진행. 빠진 건수를 `검토결과.md` 에 적는다 |
| 계산이 틀림 | 숫자를 글로 세게 시킴 | 세는 기준을 `CLAUDE.md` ⑥에 숫자로 넣는다 |

---

## 3. ② 재현성 미통과

**원인은 거의 항상 하나다. 판단 기준에 숫자가 없다.**

| 무엇이 달랐나 | 어디를 고치나 |
|---|---|
| 칸이 매번 다르다 | `CLAUDE.md` ③에 열 이름을 못 박는다 |
| 건수가 매번 다르다 | ⑥ 판단 기준에 세는 기준이 없다. `짧으면` → `300자 미만이면` |
| 순서가 매번 다르다 | 운영 스킬의 `순서` 칸에 정렬 기준 한 줄. `무엇 기준 내림차순` |
| 완전히 다르다 | ⑥에 `이상하면` · `알아서` 가 남아 있다. 그 줄을 숫자로 다시 쓴다 |
| 빈 입력에서 멈춰버림 | `CLAUDE.md` ⑤에 한 줄. `빈 파일은 건너뛰고 입력 없음으로 표시한다` |

**되묻는 말은 언제나 하나다.**

> "그걸 무엇으로 세면 알 수 있나요?"

글자 수 · 건수 · 비율 · 날짜 차이 · 개수. 무엇으로든 셀 수 있으면 숫자가 나온다.

**두 번이 완전히 같을 필요는 없다.** 다른 이유를 한 줄로 설명할 수 있으면 통과다.
발표에서 "여기가 매번 달라지는데 이유는 이것입니다"라고 말하면 그게 좋은 발표다.

## 4. ③ 안전 미통과

**여기는 못 봐준다. 셋 다 통과해야 한다.**

| 증상 | 이렇게 합니다 |
|---|---|
| 쓰기 담당자가 둘 이상 | 한 명만 남기고 나머지의 `tools` 에서 `Write` 와 `Edit` 를 뺀다 |
| `tools` 줄이 아예 없음 | 손 제한이 없다는 뜻이다. 읽기만 하는 담당자에게 `tools: Read, Glob, Grep` 을 넣는다 |
| 결과에 사람 이름이 있음 | 이름을 지운 사본으로 바꾼다. 발표도 사본으로 한다 |
| 회사 자료라 못 보여줌 | 이름을 지운 사본으로 발표하면 된다. 감점 없다 |
| 폴더 이름에 회사명이 있음 | 폴더 이름을 바꾼다. 발표 화면에 폴더 이름이 뜬다 |
| 삭제나 발송이 있는데 멈춤이 없음 | `CLAUDE.md` ⑤에 그 동작을 적는다. 그리고 실제로 걸리는지 한 번 시험한다 |

**멈춤이 실제로 걸리는지 시험하는 법**

멈춰야 하는 상황을 일부러 만든다. 예를 들어 결과 파일을 이미 있는 이름으로 덮어쓰게 해 본다.
말로 "멈출 겁니다"는 확인이 아니다.

## 5. 시간이 밀릴 때

전체 30분이다. `SKILL.md` 의 배분은 이렇다.

| STEP | 무엇 | 분 |
|---|---|---|
| 0 | 폴더 경로 받고 가진 것 확인 | 3 |
| 1 | ① 품질 | 5 |
| 2 | ② 재현성 (두 번 돌린다) | 9 |
| 3 | ③ 안전 | 5 |
| 4 | 미통과 고치기 | 4 |
| 5 | 검토결과.md 와 검토결과.html | 4 |
| | 합 | 30 |

밀리면 아래 순서로 줄인다.

```
① STEP 2의 "이상한 입력" 시험을 뺀다
   그 한 항목만 "확인 못 함"으로 적는다. 합격선은 그대로 4개 중 3개다
② STEP 4의 미통과 고치기를 뒤로 미룬다      (검토결과.md 에 적기만)
③ STEP 1 품질을 결과 1건만 보고 넘어간다

★ 절대 줄이지 않는 것
  · ③축 안전 세 항목
  · 두 번 돌려 보는 것 자체
  · 검토결과.md 와 검토결과.html 을 남기는 것
```

**안전을 못 보고 나가면 발표에서 사고가 난다.** 실명이 화면에 뜬 이력이 있다.

## 6. 무엇이 없을 때의 최소 만들기

### CLAUDE.md 가 없다

담당자 파일과 결과 파일을 읽어 초안을 만들고 확인만 받는다. 여섯 칸이다.

```
① 이 폴더는 무엇을 하는 곳인가
② 자주 쓰는 자료는 어디에 있나
③ 결과는 어디에 어떤 형식으로 남기나
④ 절대 하지 말 것
⑤ 언제 멈추고 사람에게 물을 것인가
⑥ 판단 기준        ← 세 줄. 숫자가 들어가야 한다
```

각 칸은 세 줄을 넘기지 않는다. ④와 ⑤는 수강생이 직접 고치게 한다.
각자 사정이라 모델이 알 수 없다.

### 담당자가 없다

한 명만 만든다. 결과 파일에 쓰는 사람 한 명이면 검토가 성립한다.

```
기획안이나 CLAUDE.md 를 읽고 담당자 한 명을 .claude/agents/ 에 만들어줘.
맡은 일과 손의 크기를 정의에 적고, 손 제한은 반드시 tools 로 걸어줘.
```

**5회차에 앱을 껐다 켜는 경우는 여기 하나뿐이다.** 새로 만드는 폴더가 없기 때문이다.
`.claude/agents/` 폴더를 이 자리에서 처음 만들었으면 **앱을 완전히 껐다 켜야** 인식된다.
껐다 켜라고 말하기 직전에 돌아와서 칠 문장을 함께 준다.

    에이전트 검토 이어서

이 경우가 아니면 껐다 켜라는 말을 꺼내지 않는다.

### 결과 파일이 없다

지금 한 번 돌린다. 그것이 ②축의 1회차 실행이 된다. 그러면 한 번만 더 돌리면 된다.

## 7. 판정 문구 모음

수강생에게 돌려줄 때 이 모양으로 말한다.

```
품질 4/4 통과입니다.
재현성 3/4 통과입니다. 빈 입력에서 멈추는 것 하나가 걸렸는데, CLAUDE.md ⑤에 한 줄 넣으면 됩니다.
안전 2/3 미통과입니다. 쓰기를 가진 담당자가 둘입니다. 이건 고치고 가야 합니다.
```

**개수로 말한다.** "대체로 괜찮습니다"는 판정이 아니다.
