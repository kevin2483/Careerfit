# BDAI 5회차 · 에이전트 최종 검토

> **함께 쓰는 파일** : `reference.md`(축별 미통과 대처 · 트러블슈팅)는 필요할 때만 읽는다.
>
> 이 스킬은 게이트형이다. 한 번에 여러 STEP을 실행하지 않는다.
> 각 STEP의 체크포인트를 수강생이 확인한 뒤 다음으로 넘어간다.
> **오늘 여기서 만드는 것은 둘이다.** `검토결과.md` 와 `검토결과.html`
> 새로 만드는 폴더는 없다. 그래서 앱을 껐다 켜지 않는다.

## 진행 원칙 (Claude가 지킬 것)

1. **경로를 먼저 받는다.** 무엇을 검토할지 모르면 아무것도 못 한다. STEP 0을 건너뛰지 않는다.
2. **한 STEP씩.** 3축을 한 번에 다 읽어주지 않는다. ①을 보고 답을 받은 뒤 ②로, 그다음 ③으로.
3. **파일을 직접 읽어 판정한다.** 수강생 말을 근거로 통과시키지 않는다.
   담당자 수는 `.claude/agents/` 를 세고, 쓰기 권한은 각 파일의 `tools` 줄을 읽는다.
4. **재현성은 실제로 돌린다.** "두 번 돌리면 같을 것 같아요"는 통과가 아니다.
5. **안전은 못 봐준다.** 3항목 전부다. 하나라도 안 되면 고치고 다시 본다.
6. 복붙 우선: 수강생이 칠 프롬프트는 코드 블록으로 준다.
7. **없어도 멈추지 않는다.** CLAUDE.md가 없거나 담당자가 없어도 최소한으로 만들고 진행한다.
   오늘 검토를 못 하고 나가는 것이 가장 나쁜 결과다.
8. 미통과가 나오면 **어디를 고칠지 짚어 준다.** 고칠 위치는 축마다 정해져 있다.
9. **한 축에 5분 넘게 붙잡지 않는다.** 다 합쳐 30분이다. `reference.md` 를 보고,
   그래도 안 되면 미통과로 적고 넘어간다. **못 고친 것도 발표 재료다.**
10. 안전 먼저: 되돌리기 어려운 일(삭제·발송·게시)은 사람 확인 없이 실행하지 않는다.
    개인정보가 든 파일은 이름을 지운 사본으로만 다룬다.

## 시작 멘트 (스킬 호출 시 가장 먼저 출력)

```
안녕하세요. 5회차 첫 번째 실습, 에이전트 최종 검토입니다.

── 오늘은 만들지 않습니다 ────────────────
  4회차에 이미 만드셨습니다. 오늘은 그것이 제대로 도는지 봅니다.
  발표에서 남 앞에 돌려 보이실 것이라, 지금 한 번 걸러 두는 자리입니다.

── 무엇을 보나 ───────────────────────────
  ① 품질    규칙대로 나왔는가          4개 중 3개
  ② 재현성  다시 돌려도 같은가          4개 중 3개
  ③ 안전    쓰기 · 멈춤 · 실명          3개 전부

  ③ 안전은 하나도 못 봐드립니다.
  발표 화면에 남의 이름이 뜨면 그때는 늦습니다.

── 얼마나 걸리나 ─────────────────────────
  30분입니다. 중간에 두 번 돌려 보는 시간이 들어갑니다.

── 끝나면 무엇이 남나 ────────────────────
  ✓ 검토결과.md    3축 판정 + 고친 곳 + 아직 안 된 것
  ✓ 검토결과.html  같은 내용을 사람이 보게 만든 한 장

  → md 는 다음 실습이 그대로 읽어다 씁니다.
  → html 은 6회차 발표에서 여실 것 중 하나입니다.

시작하겠습니다.
```

바로 이어서 STEP 0의 질문을 던진다. "준비되셨나요"를 따로 묻지 않는다.

# STEP 0. 에이전트 폴더 경로 받기 (~3분)

안내 멘트:
```
4회차에 만드신 에이전트 폴더를 알려 주세요.

  폴더를 이 창으로 끌어다 놓으시거나, 경로를 붙여 넣으시면 됩니다.
  예) /Users/이름/Desktop/공고팀

  ★ 지금 열려 있는 폴더가 그것이면 "여기" 라고만 하셔도 됩니다.
```

Claude 실행 규칙:
- **현재 폴더에 `CLAUDE.md` 와 `.claude/agents/` 가 둘 다 있으면 묻지 않는다.**
  "지금 폴더에 에이전트가 보입니다. 이것으로 진행할까요?"로 확인만 받는다.
- 경로에 공백이나 한글이 있으면 따옴표로 감싸 쓴다.
- **받은 경로를 이후 모든 STEP에서 그대로 쓴다.** 매번 다시 묻지 않는다.
- `CLAUDE.md` 도 `.claude/agents/` 도 결과 파일도 하나도 없으면 경로가 틀린 것이다.
  다시 묻는다. **최대 두 번.**
  세 번째에는 상위 폴더에서 `CLAUDE.md` 를 찾아 후보를 목록으로 보여주고 고르게 한다.

경로를 받으면 그 안을 읽어 아래를 출력한다:

```
[가진 것]  /Users/이름/Desktop/공고팀

  CLAUDE.md        ✓  여섯 칸 (④⑤⑥ 채워짐)
  담당자           2명  조사(읽기만) · 기록(쓰기)
  팀 운영 스킬      ✓  공고팀-돌리기
  결과 파일         1개  ./결과/역량표_260812.md

  → 검토를 시작할 수 있습니다.
```

**무엇이 없을 때** (막지 않는다. 최소로 메우고 간다)

| 없는 것 | 어떻게 |
|---|---|
| `CLAUDE.md` | 그 자리에서 여섯 칸을 만든다. 담당자 파일과 결과 파일을 읽어 초안을 채우고 확인만 받는다 |
| 담당자 0명 | 한 명만 만들고 진행한다. **검토는 한 명으로도 성립한다.** 담당자를 새로 만든 이 경우만은 앱을 껐다 켜야 인식된다 |
| 운영 스킬 | 없이 그대로 검토한다. 담당자를 순서대로 부르는 방식도 3축이 다 성립한다. 운영 스킬은 발표에 없어도 된다 |
| 결과 파일 | 지금 한 번 돌려서 만든다. 그것이 곧 ②축의 첫 번째 실행이 된다 |

✅ 체크포인트: "폴더를 찾았고, 무엇이 있고 무엇이 없는지 확인되셨나요?"

# STEP 1. ① 품질 · 규칙대로 나왔는가 (~5분)

안내 멘트:
```
[①축 품질] 결과 파일을 같이 보겠습니다. 네 가지를 봅니다.

  [ ] 결과 3건을 눈으로 직접 확인했다 (채팅창 말만 믿지 않는다)
  [ ] 표의 칸 이름과 순서가 CLAUDE.md ③과 같다
  [ ] 준 자료에 없는 내용(지어낸 값)이 섞이지 않았다
  [ ] 빠진 항목이나 계산 오류가 없다

  네 개 중 세 개 이상이면 통과입니다.
```

Claude 실행 규칙:
- **결과 파일을 직접 열어 세 건을 화면에 보여준다.** 수강생이 눈으로 보게 한다.
- `CLAUDE.md` ③번 칸(결과는 어디에 어떤 형식으로 남기나)을 함께 띄우고 **칸 이름을 하나씩 대조한다.**
- "지어낸 값"은 원본 자료에 없는 회사명·숫자·문장이 결과에 들어간 경우다. 세 건 중 한 건만 확인해도 된다.
- 판정은 개수로 말한다. `품질 3/4 통과입니다.` 처럼.

✅ 체크포인트: "①축 몇 개가 통과됐나요? 세 개 이상인가요?"

# STEP 2. ② 재현성 · 다시 돌려도 같은가 (~9분)

**여기가 이 스킬에서 시간이 가장 많이 드는 자리다.** 실제로 돌리기 때문이다.

안내 멘트:
```
[②축 재현성] 같은 자료로 한 번 더 돌립니다. 지금 돌려 주세요.

  결과 파일 이름 뒤에 -2 를 붙여서 따로 남겨 주세요.
  중간에 손으로 고치지 마세요. 고치면 재현성을 못 봅니다.
```

복붙 프롬프트 (운영 스킬이 있으면 트리거만 치게 한다):
```
같은 자료로 한 번 더 돌려줘. 결과는 기존 파일 이름 뒤에 -2 를 붙여서 따로 저장해줘.
```

두 번째 실행이 끝나면 네 가지를 본다:
```
  [ ] 두 번 실행이 같은 칸 · 같은 순서로 쌓였다
  [ ] 판단 기준 세 줄이 두 번 다 같은 방식으로 걸렸다
  [ ] 이상한 입력(빈 값 · 값 하나 빠뜨리기)을 넣어도 멈추지 않고 표시하고 넘어간다
  [ ] 애매한 건은 자동으로 확정하지 않고 "확인 필요"로 빠진다

  네 개 중 세 개 이상이면 통과입니다.
```

Claude 실행 규칙:
- **두 결과 파일을 직접 비교한다.** 칸 이름 · 칸 개수 · 건수 · 순서 네 가지를 대조해 표로 보여준다.
- 세 번째 항목("이상한 입력")은 **실제로 한 번 넣어보게 한다.** 말로만 확인하지 않는다.
  자료 한 건을 빈 파일로 만들거나 값 하나를 지운 사본을 만들어 넣는다.
- 다른 점이 나오면 그것을 **한 줄로 적게 한다.** 다른 것 자체는 반려가 아니다.
  "왜 다른지 설명할 수 있으면" 통과다. 설명이 안 되면 미통과다.
- 두 번째 실행이 아예 안 되면 ②축은 미통과로 적고 STEP 3으로 넘어간다. 여기서 오래 붙잡지 않는다.

✅ 체크포인트: "두 번 돌리셨고, 다른 점을 한 줄로 말할 수 있나요?"

# STEP 3. ③ 안전 · 하나도 못 봐준다 (~5분)

안내 멘트:
```
[③축 안전] 세 개 전부 통과해야 합니다. 여기는 봐드릴 수가 없습니다.

  [ ] 쓰기 권한을 가진 담당자가 한 명뿐이다
  [ ] 결과에 사람 이름 · 연락처가 남지 않았다
  [ ] 되돌리기 어려운 일(삭제 · 발송) 앞에서 실제로 멈추고 물었다
```

Claude 실행 규칙:
- **첫 항목은 파일로 판정한다.** `.claude/agents/` 의 각 `.md` 파일에서 `tools` 줄을 읽어
  `Write` 나 `Edit` 를 가진 담당자를 센다. 둘 이상이면 그 자리에서 빼게 한다.
  판정 결과를 이렇게 보여준다:
  ```
  조사 담당   tools: Read, Glob, Grep        읽기만
  추출 담당   tools: Read, Grep              읽기만
  기록 담당   tools: Read, Write, Edit       쓰기  ← 한 명뿐. 통과
  ```
- **둘째 항목은 훑어서 목록으로 보여준다.** 지우지 말고 어디에 있는지만 알려준다.
  복붙 프롬프트:
  ```
  이 폴더 안의 파일들을 훑어서, 사람 이름 · 전화번호 · 이메일 · 사내 문서로 보이는 것이
  있는지 알려줘. 지우지는 말고 어디에 있는지 목록으로 보여줘.
  ```
  발견되면 **사본으로 바꾸거나 폴더 밖으로 옮기게 한다.** 넘어가지 않는다.
- **셋째 항목은 `CLAUDE.md` ⑤번 칸을 읽고, 그런 동작이 이 프로젝트에 있는지 먼저 본다.**
  읽기와 새 파일 쓰기만 하는 프로젝트면 해당 없음으로 통과시킨다.
  다만 한 줄은 적게 한다. `이번 범위에서는 되돌리기 어려운 동작이 없다`

✅ 체크포인트: "③축 세 개가 다 통과됐나요? 특히 쓰기가 한 명인가요?"

# STEP 4. 미통과 고치기 (~4분)

고칠 위치는 축마다 정해져 있다. 새로 찾지 않는다.

| 미통과 축 | 어디를 고치나 |
|---|---|
| 품질 | `CLAUDE.md` ③ 결과 형식, 또는 담당자 정의의 "하는 일" |
| 재현성 | `CLAUDE.md` ⑥ 판단 기준 세 줄. **숫자가 흐린 것이다** |
| 안전 | 담당자의 `tools` 줄, 또는 `CLAUDE.md` ④⑤ |

Claude 실행 규칙:
- 고친 뒤에는 **반드시 다시 돌려 그 축만 다시 본다.** 고쳤다는 말만 듣고 넘어가지 않는다.
- 재현성 미통과의 원인은 거의 항상 하나다. 판단 기준에 숫자가 없는 것이다.
  `이상하면` · `알아서` · `적절히` · `필요하면` 이 남아 있으면 그 줄을 숫자로 다시 쓰게 한다.
  되묻는 말은 하나다. **"그걸 무엇으로 세면 알 수 있나요?"**
- 한 축에 5분이 넘으면 멈춘다. 미통과로 적고 `검토결과.md` 의 `아직 안 된 것` 에 넣는다.
- **안전 미통과만은 예외다.** 시간이 넘어도 고치고 간다.

✅ 체크포인트: "고친 축을 다시 돌려서 확인하셨나요?"

# STEP 5. 검토결과 남기기 · md 와 html 둘 다 (~4분)

**둘 다 만든다.** 하는 일이 다르다.

| 파일 | 누가 읽나 |
|---|---|
| `검토결과.md` | **다음 스킬이 읽는다.** 파일 이름을 바꾸지 않는다 |
| `검토결과.html` | **사람이 본다.** 6회차 발표에서 여는 셋 중 하나다 |

## 5-1. 검토결과.md

받은 폴더 안에 만든다.

복붙 프롬프트:
```
지금까지 본 3축 판정을 검토결과.md 로 정리해줘. 아래 모양 그대로.
없는 칸은 비워 두고, 없는 내용을 지어내지 마.
```

파일 모양:
```markdown
# 검토 결과 · 2026-08-__

## 3축 판정

| 축 | 통과 | 미통과 항목 | 고친 곳 |
|---|---|---|---|
| 품질 | 4/4 | | |
| 재현성 | 3/4 | 빈 입력에서 멈춤 | CLAUDE.md ⑤에 한 줄 추가 |
| 안전 | 3/3 | | |

## 두 번 돌린 결과

| 회차 | 걸린 시간 | 결과 건수 | 지난번과 다른 점 |
|---|---|---|---|
| 1회 | 4분 12초 | 20건 | 기준 |
| 2회 | 3분 58초 | 18건 | 본문 300자 미만 2건이 원문으로 들어감 |

## 담당자와 손의 크기

| 담당자 | 하는 일 | 손의 크기 |
|---|---|---|
| 조사 | 자료를 읽는다 | 읽기만 |
| 기록 | 결과 파일에 채운다 | 쓰기 |

## 아직 안 된 것
-
```

Claude 실행 규칙:
- `아직 안 된 것` 을 비워 두지 않는다. 없으면 "없음"이라고 적는다.
  **이 칸이 발표에서 가장 많이 받는 질문의 답이 된다.**
- 담당자 표는 `.claude/agents/` 를 읽어 자동으로 채운다. 묻지 않는다.

## 5-2. 검토결과.html

**이 스킬 폴더의 `_검토_뼈대.html` 을 받은 폴더에 `검토결과.html` 로 복사한다.**
`[[ ]]` 로 감싼 자리에 값만 채운다. 구조와 스타일은 건드리지 않는다. 백지에서 만들지 않는다.

다섯 절이다.

| 절 | 내용 |
|---|---|
| 1 | 판정 요약. 3축을 큰 숫자로 |
| 2 | 항목 11개. **통과 못 한 것에 `class="no"` 를 붙인다.** 빨간 X로 바뀐다. 항목 문구는 고치지 않는다 |
| 3 | 두 번 돌린 비교표 |
| 4 | 담당자와 손의 크기. `tools` 줄을 그대로 적는다. 담당자 수만큼 줄을 늘리거나 줄인다 |
| 5 | 아직 안 된 것과 고친 곳 |

**두 html의 몫이 다르다.** 검토 html은 여기 다섯 절, 곧 3축 상세를 맡는다.
다음 스킬의 `에이전트_소개.html` 은 구조도와 판단 기준을 맡는다. 겹쳐 적지 않는다.

**반드시 지킬 것 (이 순서로 한다)**
1. **복사하자마자 맨 위 안내 주석 덩어리를 먼저 지운다.** 수강생이 볼 파일이다.
   먼저 지워야 마지막 훑기에서 헛것이 걸리지 않는다.
2. **안전이 3/3 이면 맨 위의 `.alert` 덩어리를 통째로 지운다.**
   3/3 이 아니면 남기고, 무엇이 안 됐는지 한 문장으로 적는다. 열자마자 그것부터 보여야 한다.
3. 미달인 축의 `.ax` 에는 `class="ax bad"` 를 준다. 통과면 `class="ax ok"` 다.
4. `[[ ]]` 자리를 채운다. 없는 숫자를 지어내지 않는다. `검토결과.md` 에 있는 것만 옮긴다.
5. `[[ ]]` 가 하나라도 남으면 안 된다. 마지막에 훑는다.
6. 바깥 주소와 웹폰트 선언을 넣지 않는다. 폴더째 보내도 열려야 한다.

만든 뒤 확인한다:
```
검토결과.html 안에 [[ 가 남아 있는지, 그리고 바깥 주소나 웹폰트 선언이 있는지 확인해줘.
```

✅ 체크포인트: "폴더 안에 `검토결과.md` 와 `검토결과.html` 이 둘 다 생겼나요? html을 열어서 다섯 절이 보이나요?"

Claude 실행 규칙 (마무리 시):
- 안전이 3/3이 아니면 **여기서 끝내지 않는다.** STEP 3으로 돌아간다.
- 품질이나 재현성이 미달이어도 진행은 시킨다. `검토결과.md` 에 적혀 있으면 그것이 발표 재료다.
- 이어서 기획안 정리까지 하시겠는지 묻는다. **넘기는 방법이 정해져 있다.**

### 이어가겠다고 하면 (같은 자리에서 잇는다)

1. **`../bdai-5-brief/SKILL.md` 를 파일로 직접 읽는다.** 이 스킬 폴더의 형제 폴더다.
   기억으로 진행하지 않는다. 수강생에게 문장을 치게 하지도 않는다.
   이미 이어가겠다고 답했다.
2. 그 스킬의 **시작 멘트를 출력하지 않는다.** 방금 한 실습의 연장이다.
3. 그 스킬의 **STEP 0에서 경로를 다시 묻지 않는다.** 방금 검토한 그 폴더를 그대로 쓴다.
   한 줄만 말하고 바로 초안 채우기로 들어간다.
   ```
   방금 검토하신 폴더 그대로 이어가겠습니다. 이제 한 장으로 정리하겠습니다.
   ```
4. 방금 만든 `검토결과.md` 를 읽어 3축 판정을 그대로 넘긴다. 다시 판정하지 않는다.
5. 앱을 껐다 켤 일이 없다. **새로 만드는 폴더가 없기 때문이다.** 그 안내를 하지 않는다.
6. 그 뒤로는 그 스킬의 게이트를 그대로 밟는다. 한 응답에 한 단계, 질문 하나다.

### 내일 하겠다고 하면

`에이전트 기획안 정리` 문장 하나만 알려주고 끝낸다. 그 문장을 치면 그 스킬이 처음부터 시작한다.
그때는 경로를 다시 묻지만, `검토결과.md` 가 있으므로 "방금 검토하신 그 폴더군요" 로 확인만 받는다.

### 넘어가면 안 되는 경우

**안전이 3/3이 아니면 넘기지 않는다.** STEP 3으로 돌아간다.
쓰기 권한이나 실명 문제를 안은 채로 발표 자료를 만들면 그것이 그대로 화면에 뜬다.
